# AI向け引き継ぎ

## 30秒で分かる現在地

個人用のNAS読書アプリをChatGPT Workで段階的に作ってきた。利用者は実際にAPKを入れ、スクリーンショットとセルフテストで問題を報告している。最新配布版は0.8.6-preview、versionCode 64。今回の引き継ぎは新しいアプリ版ではなく、同じソースに資料を足したもの。

AndroidはJava Activity＋ローカルWebView。画面は `app/src/main/assets/dsbooks-prototype.html` と後続JS。音声は内蔵LibVLC＋Androidメディアサービス、PDFはPdfRenderer、EPUBは独自解析とWebView、CBRはJunrar。PC側はPython/Tkinterの表紙・メタデータ生成ツール。

## 利用者が重視すること

- 実際に使えるAPKをこちらでビルドして渡す。ソースや手順だけで止めない。
- 既存フォルダ構造・蔵書・読書位置を保つ。Calibreフォルダは過去のバックアップであり現行管理ではない。
- 追加NASサーバーなしで、Markdown＋JSON＋既存NASのファイル操作を使う。将来NAS内でPCツール相当を動かすのは任意。
- 小説EPUBの朗読、現在ページからの開始、朗読追従・強調、コミック閲覧、大きなM4Bの再生が重要。
- 著者のフォルダ横断ジャンプより、同じフォルダ内のシリーズ・巻数が重要。
- 実機テストは利用者が後から行う。実装と自動テストを進め、独立したチェックリストを付ける。
- リンク切れや未保存APKを繰り返さない。上書き更新できる署名を維持する。

## すでに実装しているのに再発明しやすい機能

0.5.3でLibVLC内蔵、0.5.4でストリーミング＋並行保存、0.6.0で前景時NAS同期、0.7.0でTV/Auto試験対応と表紙ウィジェット、0.8.0で保存済み音声Cast・朗読追従・大量蔵書対策、0.8.2でSVG画像EPUB/CBZ/CBR、0.8.3〜0.8.5でシーク・フォント・縦書き・再接続、0.8.6でリストと並べ替えまで存在する。詳細な限界はCURRENT_STATEを参照。

## 最初の作業

1. 最新ユーザー指示と `BACKLOG.md` を照合する。すべての要望は `REQUIREMENTS.md` とJSON対応表で追える。
2. `BUILD_AND_RELEASE.md` に従って環境と鍵の所在を確認する。鍵はこのZIPに入っていない。
3. `TESTING.md` の関連テストを確認。必要なら選択した回帰テストを実行する。
4. `ARCHITECTURE.md`、自動生成した `reference/native-bridge.md`、`reference/storage-keys.json` から変更箇所へ進む。
5. 実装後に `CHANGELOG.md`、状態表、実機チェックを更新する。

## 情報の優先順位

最新ユーザー指示 → 現行ソース＋実機報告 → CURRENT_STATE/BACKLOG → CHANGELOG/最新版テスト記録 → 過去資料。

ROADMAPは原文を保持しているため重複・古い段落がある。例えば「Auto未実装」「NAS同期未実装」「TTS追従未実装」は初期版の記述で、現在全体を説明する文ではない。

## 信頼できる事実と境界

0.8.6配布APKはCRC、全アセット照合、v2/v3署名、同一証明書、保存後再取得のSHA-256を確認した。0.8.6のリスト操作と0.8.5の主要機能をブラウザの模擬ブリッジで検証した。一方、全実機の読書表示・実NAS・スピーカー・Bluetooth・Cast・Auto・TVの動作保証はしていない。版ごとの未チェック項目を引き継ぐ。

今回の整理では元のアプリ機能を変更していない。GitHub用にフォントを別フォルダへ退避し、READMEと案内・検証スクリプトを追加した。既存のアプリソース差分は検証報告を参照。
