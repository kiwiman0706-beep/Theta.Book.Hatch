# 開発経緯と判断

これは会話と保存資料から再構成した経緯であり、全文チャットやGitログではありません。正確な版が特定できない改善は時期のまとまりとして記載します。

## 1. NAS上のファイルを読める状態へ

当初はSynologyの共有フォルダから蔵書一覧を取得する試作。QuickConnectを前提にせずTailscale経由のDSM APIを採用した。Calibreフォルダは昔のバックアップであり、現在のフォルダ整理を尊重する方針へ固定。単に外部アプリへ渡すだけでなく、EPUB・音声本をアプリ内部で利用したいという要望が中心になった。

ログイン保持、2FA入力、画面でのバージョン表示が必要になった。EPUBのAndroid XMLパーサ機能非対応、外部アプリ選択が出る、本棚が10冊から保存済み2冊だけになるなどの問題を経て、内部表示とスキャンの保持・範囲指定を改善した。

## 2. 読書体験と本棚の設計

モーダルが小さい、画像の解像度が低い、フォント拡大で章タイトルだけが巨大になりページ画像が小さくなるという報告。変換EPUBでは画像と文字のズームを分ける必要があると判明し、全画面・画像拡大／パン・画像専用表示へ進めた。元画像以上の情報を生成する改善とは区別する。

フォルダごとに横へ本を並べ、棚を縦へ閲覧するスケッチを採用。Delicious Library風の木目、読書中と新しい本の左寄せ、付箋・進捗、音声本の上側に出るレコード盤を採用。利用者から「木目を緑にしない」と修正があり、木目の棚と黒／緑のヘッダー・フッターを分けることが重要なデザイン制約になった。

その後、フォルダを開いた画面は横一列ではなく折り返し、戻るとホームへ戻るよう改善。0.8.6で一覧性を重視したリスト表示と詳細な並べ替えを追加した。

## 3. キャッシュとサーバーレス管理

未ダウンロード本にも表紙を出すため、PCで表紙を抽出しNAS上に小さなキャッシュを置く方式を採用。Windows GUIとセットアップ／インストーラー作成スクリプトを追加した。完成したSetup.exeを配布したという証拠はない。

thumbs.db共用は採用を見送り。Gemini等で外部表紙を探す案は将来の任意機能。PCツール相当を将来Synology内で動かす案は残すが、NAS管理アプリを必須にはしない。

シリーズ管理を重視し、Obsidian互換の本ごとのMarkdownを編集元、catalog.jsonを生成索引、端末別JSONを読書進捗として分離。元ファイル内へのID埋め込みではなく、別ファイルの安定IDとハッシュで改名を追跡する方針になった。

## 4. 音声と大容量ファイル

音声再生画面を閉じると音だけ続き停止できない問題から、ミニプレイヤーとOSの通知・メディアセッションを導入。EPUB朗読も同じ操作系を利用する。

大きいM4Bが再生できず、Amazon Music等でも失敗したが外部VLCでは成功。0.5.2の診断で、ファイルサイズは一致する一方、Android標準パーサが音声トラックを取得できなかった。容量だけの問題ではなく解析／コーデック互換性を優先し、0.5.3でLibVLCを内蔵した。

0.5.4ではNASストリーミングと保存を並行できるようにした。ただし単一のダウンロードキャッシュを再生と共有する方式ではなく、重複通信がある。ここは現在も改善課題。

同名のM4BとPDFは1冊の音声本＋添付資料として扱い、プレイヤー内でPDFを参照する。章一覧、共通メモ、ファイル共有を追加。NotebookLMへの自動送信・自動要約を実装したわけではない。

## 5. 長い小説と朗読

章単位だけの進捗では長い本文を読んでも30%付近から動かず、再開も困難だった。章内ページ位置と本文量ベースの重み付けを導入。さらに「朗読が章頭から始まる」報告に対応し、現在ページから開始、次ページへ追従、読み上げ範囲強調、手動ページ移動での追従解除／復帰を実装した。

0.8.3でジャンプ用シークバーとフォント、0.8.4で提供フォント、0.8.5で縦書き切り替えを追加。章をまたぐ自動朗読と完全な縦組再現は別課題として残る。

## 6. 規模・端末・配布

蔵書が増えて起動時に白画面で固まる報告から、0.8.0で初期描画とDOM量を制限し、全件検索と表示ページを分離。フォルダ名から接頭辞を外しても残る問題は0.8.1で対象範囲と保存済み保護を分けて改善。

TV・Auto・Cast・ウィジェットへ拡張。試験対応を実機確認済みと誤認しない。EPUBコミックのSVG画像が白紙になる報告から0.8.2でSVG画像とCBZ/CBRへ対応した。

SDKがない／署名鍵がないとしてAPKを渡せなかった説明や、リンク切れ・保存失敗・インストール不可が繰り返され、利用者は実行可能な配布物を強く求めている。0.8.5は保存に失敗した版を復元して再配布。0.8.6では出力APKの不整合を再署名・再検証してから保存し、取得後ハッシュも確認した。単なるビルド成功メッセージだけで配布しない。

## 将来も維持する判断

原本を変更しない／サーバーを必須にしない／利用者のデータを失わない／実機確認と自動確認を分ける／書籍・音声を外部AIへ自動送信しない／著者横断ジャンプより棚内シリーズを優先する。
